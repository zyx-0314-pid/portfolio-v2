Veyra

Veyra is a multi-tenant feedback and review-management platform designed for organizations to collect public feedback through QR-based entry points, moderate and manage responses, publish approved reviews, manage subscriptions and access, and operate the platform through administrative and developer tooling.

As System Architect and Lead Developer at Nyebe Creations Studio, I designed the application structure, tenant and authorization boundaries, backend-service integration, operational tooling, security visibility, and deployment workflow while remaining hands-on with full-stack implementation.

Multi-Tenant Architecture

Veyra utilizes a shared application and database architecture with tenant-aware record scoping. Every organization resource is bound to a verified tenant identifier, ensuring strict resource scoping across all platform queries.

Tenant-scoped data entities:

  • Organization Members: Users registered under a specific organization.
  • Feedback Submissions: Pending and archived customer submissions.
  • Reviews: Moderated, approved, or rejected public review records.
  • Role Definitions: Organization-specific custom role templates.
  • Subscription Records: Billing status, tier limits, and feature flags.

Database Isolation Model

The platform architecture distinguishes between default shared tenancy and requirement-driven isolation models:

DEFAULT: Shared Tenant-Aware Data All organization data resides within shared collection structures guarded by explicit tenant ID scoping and backend permission rules.
OPTIONAL: Requirement-Driven Isolation Architecture supports provisioning dedicated isolated database instances for enterprise deployments requiring strict physical data separation.

Core Tenancy Principle

In Veyra, a user request is never authorized simply because the target record exists in the system. The platform evaluates identity, organization context, and specific role capabilities simultaneously before granting access:

Authenticated User Request

        ↓

Custom Role-Based Access Control (RBAC)

Veyra implements a multi-layered security and authorization architecture combining server-side application logic, Appwrite document permissions, and database-stored role definitions.

Role family hierarchy:

  • platform_owner: Global system administrator managing platform-wide tenants, billing, and operational health.
  • org_admin: Organization administrator managing local members, custom roles, subscription settings, and review policies.
  • dev: Developer role with access to system logging, API tokens, and integration webhooks.
  • Configurable Role Templates: Custom organization roles defining granular capabilities for staff and moderators.

Subscription Lifecycle & Feature Access

Organization features, usage quotas, member limits, and API access are governed by subscription lifecycle management.

Key subscription capabilities:

  • Tiered Subscription Statuses: Active, Trialing, Past Due, and Canceled lifecycle states.
  • Feature Access Gates: Dynamic checks enforcing feature availability based on active subscription tier.
  • Payment Verification Workflow: Automated handling of subscription updates and access state synchronization.
Access Guardrails Subscription middleware automatically restricts administrative actions when an organization subscription enters expired or past-due states.

Observability & Security Audit Logging

Security and compliance are reinforced through structured audit logging. Sensitive administrative operations—such as role modifications, member invitations, status overrides, and subscription changes—generate immutable security audit events.

Audit Record Scoping Every audit event logs actor ID, action type, target resource, timestamp, IP context, and organization tenant ID.
System Visibility Provides studio administrators with clear visibility into security-sensitive operations across all platform tenants.

System & Architectural Constraints

Strict Tenant Data Isolation Preventing data leaks across organization boundaries required strict middleware checks on every API request.
Public Submission Abuse Protection Public-facing QR feedback forms required rate-limiting and anti-spam protection without friction for legitimate customers.
Multi-Layered Authorization Performance Evaluating role templates, organization boundaries, and Appwrite backend permissions needed to execute efficiently without causing API latency.
DevOps Automation Managing backend service updates across local, staging, and production environments required reproducible deployment scripts.

Key Technical Decisions

1. Explicit Tenant-Scoped Record Architecture

Context: SaaS application serving multiple organizations on shared infrastructure.

Decision: Bind all resource models to explicit organization IDs and enforce tenant boundary checks at the application controller layer.

2. Multi-Layered RBAC Security Boundary

Context: Different organizations require distinct user permissions and access levels.

Decision: Combine server authorization logic with database-stored role permission templates and Appwrite security rules.

3. Anonymous QR Feedback Entry Points

Context: Public customers need a frictionless way to submit reviews without creating platform accounts.

Decision: Encode organization tokens in public QR links and accept anonymous submissions into a moderated holding queue.

4. Structured Security Audit Event Pipeline

Context: Need for operational accountability and security visibility across administrative actions.

Decision: Emit immutable audit log events for all permission, member, and subscription modifications.

5. Automated CI/CD Delivery Pipeline

Context: Frequent feature updates required reliable testing and deployment automation.

Decision: Implement GitHub Actions workflows for automated testing, schema verification, and Vercel/cloud deployments.

Lessons & Retrospective

Architecture Before Implementation

Veyra demonstrated that establishing clear tenant isolation principles and RBAC models upfront prevents complex security refactoring as feature requirements grow. Designing authorization at both the application level and backend service layer ensured robust security by default.

DevOps as a Product Enabler

Automating build, test, and Appwrite schema deployment workflows early in the project allowed the studio team to iterate rapidly on new features without sacrificing stability or environment consistency.
